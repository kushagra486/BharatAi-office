# Office floor pixel-art asset spec

The office floor renders real hand-authored pixel art — a warm, light
"retro office-sim" style (cream walls, sage-green floor, wood furniture) —
generated by two scripts:

- `frontend/scripts/generate-pixel-art.py` → `tileset.{png,json}` (the floor/
  furniture/decor tileset) and `characters.{png,json}` (the shared fallback
  character rig).
- `frontend/scripts/generate-agent-sprites.py` → `characters/<agentId>.{png,json}`
  (a distinct full-body sprite per agent).

Every pixel is placed explicitly in those scripts; nothing is traced,
generated from a reference image, or pulled from a stock/licensed sprite
pack (see the project PRD's IP note) — the palette and layout are an
original take on that visual genre, not a copy of any specific game's art.
`assets.ts`'s `loadOfficeAssets()` loads the real tileset + shared rig
first and only falls back to a procedural placeholder if missing, and
independently tries each agent's distinct sheet — this doc is the contract
all of these must satisfy.

To regenerate or restyle, edit the relevant script and re-run it
(`python3 frontend/scripts/generate-pixel-art.py`,
`python3 frontend/scripts/generate-agent-sprites.py` — both require
Pillow) — or replace the output with art from any other pixel-art tool
(Aseprite, etc.) as long as it matches the spec below exactly.

## Tileset — `frontend/public/office-pixel/tileset.json` (+ PNG)

- Export format: Aseprite/TexturePacker-style JSON hash atlas, loadable via `PIXI.Assets.load()`.
- Tile size: 32×32px.
- Required tile keys (must match exactly — see `TileKey` in `assets.ts`): `floor_a`, `floor_b`, `wall_edge`, `wall_inner`, `window`, `desk`, `review_table`, `nova_office`, `plant`, `water_cooler`, `printer`, `bookshelf`, `rug_eng`, `rug_design`, `rug_data`, `rug_ops`.
- Tiles are **not** tinted at runtime, so they're authored directly in final color — sage-green floor, cream walls with a tan baseboard trim, warm wood desks/tables, a gold-trimmed `nova_office` mat, pastel department rugs — a cozy, light palette rather than the app's darker dashboard-chrome theme (the two are meant to contrast: see "Where the light theme starts and stops" below).
- The `rug_*` tiles are laid under each employee's desk keyed by department (`eng`→teal, `design`→amber, `data`→green, `ops`→rose — see `DEPT_RUG` in `pixiScene.ts`), so the two desk rows read as distinct team zones without moving anyone's fixed `home_x`/`home_y`.
- `wall_inner` partitions Nova's desk into its own small enclosed office (walls + a 2-tile door gap, see `NOVA_WALL_*` constants in `pixiScene.ts`); `window` punches a few tiles into the exterior `wall_edge` ring. `plant`/`water_cooler`/`printer`/`bookshelf` are freestanding set-dressing placed in the aisles the desks don't occupy (`DECOR_PROPS` in `pixiScene.ts`).

## Full-body character sprites

Every agent is rendered as a full-body, top-down "chibi" sprite standing/
walking at their desk — a rounded head (corner pixels left transparent to
fake roundness at this resolution), torso, arms, and legs, built from the
same block primitive as the tileset. There are two layers:

- **Shared fallback rig** — `characters.json` (+ PNG), generated by
  `generate-pixel-art.py`. Drawn in a **grayscale palette** (near-black
  outline/eyes, mid-gray shadow, light-gray base, white highlight) so
  runtime `.tint` (`CharacterSprite.ts`) reproduces each agent's identity
  color while the outline/eyes stay dark and legible under any tint. Used
  for any agent without a sheet of their own.
- **Per-agent sprites** — `characters/<agentId>.json` (+ PNG), generated by
  `generate-agent-sprites.py`. Each of the 11 agents gets a genuinely
  distinct look: its own hairstyle (short/long/ponytail/bob/spiky/bun/cap),
  hair color, and skin tone, plus a shirt colored from that agent's real
  identity color (muted toward a warm gray so it reads as fabric, not a
  flat neon fill) — so the floor sprite stays visually tied to the same
  badge/ring/roster-dot color used everywhere else in the app, without
  trying to match the dashboard portrait photo (a deliberate choice — see
  "Profile photos" below for why those are separate).
- Required frame keys for both layers (must match exactly — see
  `CharacterFrameKey` in `assets.ts`): `idle_down_0/1`, `idle_up_0/1`,
  `idle_left_0/1`, `idle_right_0/1` (2-frame idle bob per direction) and
  `walk_down/up/left/right_0..3` (4-frame walk cycle per direction) — 24
  frames total per sheet. Direction is communicated by eye placement (both
  eyes down, none up, one eye left/right) plus a small body offset per
  animation frame.
- `loadOfficeAssets()` tries each of the 11 possible per-agent files
  independently and silently skips any that 404 — fully incremental, no
  code change needed to add, remove, or restyle any single agent's sheet.

## Department badges & status dots

Not part of either sheet — these stay small vector shapes drawn directly
in `CharacterSprite.ts` (ported from the old `WalkerAvatar.tsx`'s
`ShapePath`), composited above each agent's sprite. They always carry the
agent's identity color, so shape + color stay meaningful regardless of
which rig (shared or per-agent) is rendering underneath.

## Profile photos — dashboard only

`frontend/public/office-pixel/portraits/<agentId>.png` — a real 3D-rendered
photo/portrait, one plain square PNG per agent (128×128). Used **only** on
the dashboard (`AgentAvatar.tsx`): a circular avatar in `TeamRoster` and
`EmployeeSidePanel`, falling back to an initial-letter badge in the agent's
identity color (`frontend/lib/agentColor.ts`) if `<agentId>.png` 404s. The
office floor does **not** use these — floor characters are the full-body
pixel sprites above, deliberately not trying to reproduce the portrait's
face; see `frontend/assets-src/minecraft-characters/SOURCE-README.md` for
how the portraits themselves were rendered from 3D models, if you need to
regenerate one.

## Where the light theme starts and stops

Only the office floor scene (tileset + character sprites) uses the warm/
light palette. The surrounding dashboard chrome (top HUD bar, brief input,
team roster, activity feed, approvals) keeps its existing dark theme
unchanged — the floor reads as a bright "window" into the office inside a
darker app shell, rather than a full app-wide re-theme. `OfficeFloorPixel.tsx`'s
Pixi `background` color (`0xebe6d8`, matching the wall cream) only shows
in the thin letterboxed edges around the floor canvas when its aspect
ratio doesn't exactly match the container.

## Swapping in different art later

1. Drop replacement `tileset.json`/`.png` and `characters.json`/`.png`
   into `frontend/public/office-pixel/` (tileset + shared rig), and/or
   `characters/<agentId>.json`/`.png` (per-agent overrides) — matching the
   frame/tile keys above.
2. Reload — `loadOfficeAssets()` in `assets.ts` tries real art first and
   only falls back to the procedural placeholder (for the tileset/shared
   rig) or the shared tinted rig (for an agent with no override) if
   something's missing. No other change needed.
